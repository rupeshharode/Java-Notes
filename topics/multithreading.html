Multithreading

Thread lifecycle, creation, synchronization and the memory model.

concurrencythreadssynchronized

Multithreading in Java allows multiple threads to execute simultaneously or concurrently. Threads are lightweight units of execution within a program.

It improves CPU utilization and responsiveness. We can create a thread either by extending the Thread class or by implementing the Runnable interface. The Runnable interface has a run() method in which the task is defined, and this task will be executed by the thread.

There are two types of threads:

Standard threads

Daemon threads → Daemon threads run in the background. When only daemon threads remain, the JVM exits.

To maintain concurrency, threads use locks. There are two types of locks:

Intrinsic locks → Achieved using the synchronized keyword. Only one thread can access a synchronized method or block at a time.

Explicit locks → Provide more control than synchronized. Examples include ReentrantLock, ReentrantReadWriteLock, and StampedLock.

Common Thread Methods

start() → begins execution in a new thread

run() → task logic

sleep(ms) → pause execution

join() → wait for another thread to finish

yield() → hint scheduler to switch threads

interrupt() → signal a thread to stop

setPriority(int) → set priority (1–10)

isAlive() → check if thread is running

currentThread() → get reference to current thread

Creating threads: the three ways

public class Threads {
    public static void main(String[] args) {
        // 1. Extend Thread
        Thread t1 = new Thread() {
            @Override public void run() { System.out.println("extends Thread"); }
        };

        // 2. Implement Runnable (preferred — keeps extends free)
        Runnable task = () -> System.out.println("implements Runnable");
        Thread t2 = new Thread(task);

        // 3. Thread.ofVirtual() — Java 21 virtual threads
        Thread t3 = Thread.ofVirtual().start(task);

        t1.start();   // start() spawns the thread; run() would just run inline!
        t2.start();
    }
}

synchronized: the counter race fixed

class Counter {
    private int count = 0;

    // Without this, 1000 threads x 1000 increments lose updates:
    // count++ is read-modify-write, not atomic.
    public synchronized void increment() { count++; }

    public synchronized int get() { return count; }
}

class BlockScope {
    private final Object lock = new Object();
    private int shared = 0;

    void work() {
        synchronized (lock) {        // lock only the critical section
            shared++;
        }
    }
}

volatile vs synchronized

class Status {
    // volatile guarantees visibility (no cached copy) but NOT atomicity.
    // Use it for flags; use synchronized/Locks for compound updates.
    private volatile boolean running = true;

    void stop() { running = false; }

    void loop() {
        while (running) {
            // will always see the latest value of `running`
        }
    }
}

wait / notify and interrupt

class ProducerConsumer {
    private final Object lock = new Object();
    private boolean produced = false;

    void consume() throws InterruptedException {
        synchronized (lock) {
            while (!produced) {          // ALWAYS re-check in a while loop
                lock.wait();             // releases the lock while waiting
            }
            System.out.println("consumed");
            produced = false;
            lock.notifyAll();            // wake up waiting threads
        }
    }

    void produce() {
        synchronized (lock) {
            produced = true;
            lock.notifyAll();
        }
    }
}
