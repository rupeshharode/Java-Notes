Polymorphism

Compile-time vs runtime polymorphism, overloading and overriding.

oopoverloadingoverriding

**Polymorphism **

Polymorphism means "many forms." In polymorphism, the same method name or interface can behave differently in different situations.

There are two main types of polymorphism:

Compile-Time Polymorphism (Method Overloading)

Method overloading occurs when a class has two or more methods with the same name but different parameter lists.

The parameters can differ in:

Number of arguments

Type of arguments

Order of argument types

The compiler determines which overloaded method to call at compile time.

Runtime Polymorphism (Method Overriding)

Method overriding occurs when a child class provides its own implementation of a method that it inherits from the parent class.

The method that will actually execute is determined at runtime based on the object, which is why it is called runtime polymorphism.

In short:

Overloading → Same class → Same method name → Different parameters → Compile time

Overriding → Parent-child relationship → Same method signature → Different implementation → Runtime

Example Overloading -->

class Calculator {

int sum(int a, int b) {
    return a + b;
}

float sum(float a, float b) {
    return a + b;
}

}

Example Overriding -->

class Animal { void sound() { System.out.println("Animal makes a sound"); } }

class Dog extends Animal { @Override void sound() { System.out.println("Dog barks"); } }

Animal a = new Dog(); a.sound(); // Dog barks

Runtime polymorphism: overriding

class Shape {
    double area() { return 0; }
}

class Circle extends Shape {
    private final double r;
    Circle(double r) { this.r = r; }
    @Override double area() { return Math.PI * r * r; }
}

class Rectangle extends Shape {
    private final double w, h;
    Rectangle(double w, double h) { this.w = w; this.h = h; }
    @Override double area() { return w * h; }
}

class Demo {
    public static void main(String[] args) {
        Shape s = new Circle(7);       // parent reference, child object
        System.out.println(s.area());  // Circle.area() chosen at RUNTIME
        s = new Rectangle(3, 4);
        System.out.println(s.area());  // Rectangle.area()
    }
}

Compile-time polymorphism: overloading

class Printer {
    void print(String msg) { System.out.println("String: " + msg); }
    void print(int n) { System.out.println("int: " + n); }
    void print(String msg, int copies) { /* different parameter list */ }
    // int print(String msg) {}  // NOT overloading — return type alone differs
}

Overriding rules interviewers test

class Parent {
    protected Object process() throws Exception { return null; }
}

class Child extends Parent {
    // 1. Same signature
    // 2. Access can only widen (protected -> public), never narrow
    // 3. Return type can be the same or a subtype (covariant)
    // 4. Can throw only the same, fewer, or narrower checked exceptions
    @Override
    public String process() { return "ok"; }
}

// final / private / static methods cannot be overridden
class FinalParent {
    final void lock() {}       // cannot override
    private void hide() {}     // not inherited, so nothing to override
}
