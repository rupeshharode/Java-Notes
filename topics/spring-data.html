Spring Data (JPA)

Repositories, derived queries, JPQL, pagination and relationships.

springjparepositories

Spring Data is an umbrella project in the Spring ecosystem that provides a consistent and simplified way to work with different data storage technologies. It reduces boilerplate code by providing repository interfaces and predefined methods for common database operations.

For example: - Spring Data JPA is used with relational databases such as MySQL and PostgreSQL. - Spring Data MongoDB is used with MongoDB, a NoSQL database. - Spring Data Redis is used with Redis, an in-memory data store.

Spring Data provides different repository interfaces, such as CrudRepository, ListCrudRepository, PagingAndSortingRepository, and JpaRepository, depending on the required operations.

By extending the appropriate repository interface, we can use predefined methods such as save(), findById(), findAll(), and deleteById() without writing their implementations ourselves. Spring Data generates the required repository implementation at runtime.

Therefore, Spring Data simplifies database access, reduces boilerplate code, and improves developer productivity.

** why we use repository instead of hibernate implementation entitymanager

We use Spring Data JPA repositories because they reduce boilerplate code and simplify database operations.

For example, suppose we have multiple entities, such as Student, Department, and Employee. If we use EntityManager directly, we may need to write repetitive code for operations such as saving, finding, updating, and deleting entities.

We also need to understand entity management, persistence contexts, and transaction handling.

With Spring Data JPA, we can create repository interfaces by extending JpaRepository. Spring automatically provides the implementation for common database operations at runtime.

For example, we can call studentRepository.save(student) or studentRepository.findById(id) directly from our service layer.

This reduces repetitive code and makes our application easier to maintain. However, EntityManager is still useful when we need custom queries or more control over persistence operations.

******

CrudRepository is used to perform CRUD operations on a database, while PagingAndSortingRepository is used to retrieve data with pagination and sorting. JpaRepository provides a wide range of methods by combining CRUD, list-based CRUD, and paging and sorting functionality. It also provides additional JPA-specific methods.

What is the difference between findById() and getReferenceById() in Spring Data JPA?

The main difference between findById() and getReferenceById() is how they retrieve an entity.

findById() returns an Optional containing the entity if it exists, or an empty Optional if it does not exist. It generally retrieves the entity from the database if it is not already available in the persistence context.

On the other hand, getReferenceById() may return a proxy without immediately fetching the entity's data from the database. The data is typically fetched when we access the entity's properties.

If the referenced entity does not exist, accessing its data may result in an EntityNotFoundException. Proxy behavior and when the database is queried depend on the JPA provider and persistence context.

**

What is the difference between save() and saveAndFlush() in Spring Data JPA?

The main difference between save() and saveAndFlush() is when changes are synchronized with the database.

save() saves or updates an entity in the persistence context, but it does not guarantee an immediate flush to the database. The changes may be synchronized later, such as when the transaction commits or a flush is triggered.

On the other hand, saveAndFlush() saves the entity and immediately triggers a flush of the persistence context. This synchronizes pending changes with the database without necessarily committing the transaction.

Therefore, we use save() for normal persistence operations and saveAndFlush() when we need pending changes to be synchronized with the database immediately.

********

What is the difference between CrudRepository and ListCrudRepository?

The main difference between CrudRepository and ListCrudRepository is the return type of certain methods.

CrudRepository provides basic CRUD operations, and methods such as findAll() return an Iterable.

ListCrudRepository provides similar CRUD operations, but methods such as findAll() return a List instead of an Iterable.

A List is useful when we need list-specific operations, such as accessing elements by index. Both interfaces provide methods for common database operations.

*****

What are derived query methods in Spring Data JPA? Explain with an example.

Derived query methods in Spring Data JPA are methods whose database queries are automatically generated by Spring Data based on the method name.

Instead of writing SQL or JPQL queries manually, we define methods in the repository interface using predefined keywords such as findBy, And, Or, GreaterThan, and OrderBy.

Spring Data analyzes the method name at runtime and generates the appropriate query to retrieve or manipulate data.

Derived query methods reduce boilerplate code and make database operations easier to implement and maintain.

*******

What is the difference between a derived query method and the @Query annotation in Spring Data JPA?

The main difference between a derived query method and the @Query annotation is how the query is defined.

A derived query method allows Spring Data JPA to generate a query automatically based on the method name. For example, findByDepartment(String department) retrieves students belonging to a particular department.

On the other hand, the @Query annotation allows us to explicitly write a JPQL or native SQL query. It is useful when the query is complex or cannot be expressed conveniently through a method name.

Therefore, derived query methods are suitable for simple queries, whereas @Query provides greater flexibility for complex database operations.

*****

What is the difference between JPQL and native SQL in Spring Data JPA?

The main difference between JPQL and native SQL is that JPQL is an object-oriented query language, whereas native SQL uses the database's SQL syntax.

JPQL operates on entity classes and their properties instead of directly accessing database tables and columns. It is generally database-independent because the JPA provider translates JPQL into SQL.

On the other hand, native SQL allows us to write database-specific SQL queries directly using table and column names. It is useful when we need database-specific features or complex queries that are difficult to express in JPQL.

Therefore, we use JPQL for entity-oriented, portable queries and native SQL when we need more direct control over database-specific SQL.

****

What is the difference between findById() and findAll() in Spring Data JPA?

findById() is used to retrieve a specific entity using its primary key. It returns an Optional containing the entity if it exists, or an empty Optional if it does not exist.

On the other hand, findAll() retrieves all entities of the specified type and returns an Iterable or a List, depending on the repository interface being used.

Therefore, we use findById() when we need a particular record and findAll() when we need all records.

******

What is the difference between save() and saveAll() in Spring Data JPA?

In Spring Data JPA, save() is used to save or update a single entity, whereas saveAll() is used to save or update multiple entities in one method call.

Both methods return the saved entities. save() returns a single entity, while saveAll() returns an iterable of the saved entities.

However, calling saveAll() does not necessarily mean that all entities are inserted using a single SQL statement. The actual database operations depend on the JPA provider and batching configuration.

*********

What is the difference between findById() and existsById() in Spring Data JPA?

In Spring Data JPA, findById() is used to retrieve an entity based on its primary key. It returns an Optional containing the entity if it exists, or an empty Optional if it does not exist.

On the other hand, existsById() is used to check whether an entity with a specific primary key exists in the database. It returns a boolean value: true if the entity exists and false otherwise.

Therefore, we use findById() when we need the entity's data and existsById() when we only need to check its existence.

Entities and relationships

import jakarta.persistence.*;
import java.util.*;

@Entity
public class Author {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String name;

    @OneToMany(mappedBy = "author", cascade = CascadeType.ALL, orphanRemoval = true)
    private List<Book> books = new ArrayList<>();

    public void addBook(Book b) {
        books.add(b);
        b.setAuthor(this);      // keep both sides in sync
    }
}

@Entity
public class Book {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String title;

    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "author_id")
    private Author author;
}

Repository: derived queries for free

import org.springframework.data.jpa.repository.*;
import org.springframework.data.domain.*;
import java.util.*;

public interface BookRepository extends JpaRepository<Book, Long> {

    // SQL generated from the method name
    List<Book> findByTitleContainingIgnoreCase(String keyword);
    List<Book> findByAuthorName(String name);
    Optional<Book> findByTitleAndAuthorName(String title, String author);
    boolean existsByTitle(String title);
    long countByAuthorName(String name);

    // Sorting + pagination built in
    Page<Book> findByAuthorName(String name, Pageable pageable);

    // Custom JPQL
    @Query("SELECT b FROM Book b WHERE b.title LIKE %:q%")
    List<Book> search(@Param("q") String q);
}

CRUD + pagination in a service

import org.springframework.data.domain.*;
import org.springframework.stereotype.Service;

@Service
class BookService {
    private final BookRepository books;

    BookService(BookRepository books) { this.books = books; }

    Book save(Book b) { return books.save(b); }
    Optional<Book> one(Long id) { return books.findById(id); }
    void delete(Long id) { books.deleteById(id); }

    Page<Book> page(int pageNo, int size) {
        return books.findAll(
                PageRequest.of(pageNo, size, Sort.by("title").ascending()));
    }
}
