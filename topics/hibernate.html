Hibernate

ORM fundamentals: entities, mappings, sessions, caching and HQL.

Q.1What is Hibernate, and why do we use it in Java?

Hibernate is an ORM (Object-Relational Mapping) framework for Java that is used to map Java objects to relational database tables.

In a Java application, data is represented as objects, whereas a relational database stores data in tables. Hibernate provides a mapping between these objects and database tables, so developers can work with Java objects instead of handling database operations directly.

Hibernate also reduces the need to write SQL queries and manually manage database connections. It provides APIs and methods to perform operations such as saving, retrieving, updating, and deleting data.

Compared to JDBC, Hibernate provides a higher-level abstraction. In JDBC, we generally need to manage database connections and write SQL queries manually, whereas Hibernate handles much of this work for us.

Q.2 What is ORM, and how does Hibernate implement ORM?

ORM stands for Object-Relational Mapping. Java is an object-oriented programming language, so we represent data using classes and objects. However, relational databases store data in tables and rows. ORM acts as a bridge between Java objects and relational database tables. It maps Java classes to database tables and objects to rows, so we don't need to manually convert object data into database records. Hibernate is an ORM framework that provides this functionality.

Q.3 How does Hibernate implement ORM?", you can say:

"Hibernate implements ORM by mapping Java classes to database tables and Java objects to table rows. We use annotations like @Entity, @Table, and @Id to define the mapping. When we create a Java object and save it using Hibernate, Hibernate generates the required SQL query and stores the data in the database. In this way, Hibernate reduces the need for manually writing SQL queries and converting Java objects into database records."

Q.4 What is the difference between JDBC and Hibernate?

JDBC is a Java API used to connect a Java application to a database. In JDBC, we generally establish the database connection, write SQL queries, and process the results manually. Whereas, Hibernate is an ORM framework that maps Java classes to database tables and objects to rows automatically. It manages database connections through its configuration and can generate SQL queries automatically, so we don't need to write SQL for every operation. However, if we need to write queries manually, Hibernate supports HQL, JPQL, and native SQL. The main difference is that JDBC works directly with SQL, whereas Hibernate works with Java objects and handles object-relational mapping.

JPQL stands for Java Persistence Query Language. HQL stands for Hibernate Query Language. Both are object-oriented query languages, but they are not the same.

Q.5 What is the difference between Session and SessionFactory in Hibernate?

SessionFactory is an interface in Hibernate, and SessionFactoryImpl is one of its implementations. A SessionFactory is generally created once for an application and is used to create Session objects.

A Session represents a unit of work with the database and is typically created for a particular transaction or unit of work. After the work is completed, the Session is closed.

The main difference in caching is that Session provides first-level cache, which is associated with a particular Session. SessionFactory is associated with the second-level cache, which can be shared across multiple Sessions.

Also, SessionFactory is thread-safe and can be shared across multiple threads, whereas a Session is not thread-safe and should generally be used by one thread at a time.

Q.6 What is the difference between get() and load() methods in Hibernate?

The get() and load() methods in Hibernate are used to retrieve an object from the database using its primary key.The main difference between get() and load() is how they handle an entity that does not exist.

get() immediately checks the database and returns the entity if it exists. If the entity does not exist, it returns null.

load() can return a proxy object without immediately accessing the database. If the entity does not exist, an exception can be thrown when the proxy is accessed.

Therefore, we can remember it as: get() returns null when the object is not found, whereas load() can throw an exception when the object is accessed and does not exist.

Q.7 What is the difference between save(), persist(), and saveOrUpdate() in Hibernate?

save() is a Hibernate-specific method used to save a new entity. It traditionally returns the generated identifier/serializable of the entity.

persist() is a JPA-defined method that is also supported by Hibernate. It is used to make a new entity persistent. Unlike save(), persist() returns void.

saveOrUpdate() is a Hibernate-specific method. It can be used to either save a new entity or update an existing entity depending on the entity's state.

So, save() and saveOrUpdate() are Hibernate-specific APIs, whereas persist() is part of the JPA specification.

Q.8 What are the three states of an entity in Hibernate?

There are four main entity states in JPA and Hibernate: Transient, Managed, Detached, and Removed.

Transient: When we create an entity object using the new keyword, it is initially in the transient state. It is not associated with the persistence context and is not stored in the database.

Managed: When an entity becomes associated with the persistence context, it enters the managed state. Hibernate tracks changes made to the entity and synchronizes those changes with the database during flush or commit.

Detached: When a managed entity is no longer associated with the persistence context, it becomes detached. This can happen when the persistence context is closed or when we explicitly call detach().

Removed: When we call remove() on a managed entity, it enters the removed state and is marked for deletion from the database. The actual deletion is generally synchronized with the database during flush or commit.

Q.9 First Level Caching And Second Level Caching

First-level cache is associated with a Hibernate Session. It exists for the lifetime of that Session, and each Session has its own first-level cache. It is enabled by default.

Second-level cache is associated with the SessionFactory. It can be shared across multiple Sessions and can improve performance by reducing repeated database queries. Unlike first-level cache, second-level cache generally needs to be explicitly configured with a cache provider.

So, the main difference is that first-level cache is Session-specific, whereas second-level cache is shared across multiple Sessions through the SessionFactory.

Q>10 Lazy loading in hibernate

Lazy loading is a technique in Hibernate where related data is not loaded from the database immediately. Instead, Hibernate loads the data only when it is actually accessed or needed.

For example, when we retrieve an Employee, Hibernate may load the Employee information first and load the associated Department information only when we access the Department.

Lazy loading helps avoid unnecessary database queries and can improve application performance.

Q.12 merge()

merge() is a JPA-defined method that is also supported by Hibernate. It is used to merge the state of a detached entity back into the persistence context.

The important point is that merge() does not make the original detached object managed. Instead, Hibernate copies its state to a managed entity and returns the managed instance.

For example, if an Employee object is detached and we call merge(), Hibernate returns a managed Employee object containing the state of the detached object.

Q.13 Update()

update() is a Hibernate-specific method that is traditionally used to re-associate a detached entity with the current Session. The given object becomes associated with the Session, and its changes can be synchronized with the database.

merge() is a JPA-defined method. It copies the state of a detached entity to a managed entity and returns the managed instance. The original detached object remains detached.

Therefore, the main difference is that update() re-associates the given object with the Session, whereas merge() copies its state to a managed object.

Q.14 HQL or SQL

HQL stands for Hibernate Query Language. It is an object-oriented query language provided by Hibernate and is used to query Java entities and their properties.

Unlike SQL, which works with database tables and columns, HQL works with entity classes and their properties.

For example, in HQL we write FROM Employee WHERE name = 'John', where Employee is the Java entity class.

Hibernate translates the HQL query into SQL and executes it against the database.

Q.4 Cascade

Cascade in Hibernate/JPA is used to propagate operations performed on one entity to its related entities.

For example, if a Customer has multiple Orders and we use CascadeType.REMOVE, removing the Customer can also remove its related Orders.

Cascade is not limited to delete operations. It can also be used with operations such as persist and merge. CascadeType.ALL enables all applicable cascade operations.

Q.3 Mappedby

mappedBy is used in a bidirectional relationship to specify the field in the other entity that owns the relationship.

It tells Hibernate that the current side is the inverse side and that the relationship is already mapped by the specified field on the other entity.

For example, if Department has @OneToMany(mappedBy = "department"), then the department field in the Employee entity owns the relationship.

Q.5 orphenRemovel vs cascade

Q.2 N+1 Problem

"N+1 is a Hibernate performance problem where Hibernate executes one query to fetch parent entities and then N additional queries to fetch their associated entities. For example, fetching 10 departments and then accessing employees can result in 11 queries. We can reduce this problem using JOIN FETCH, Entity Graphs, or batch fetching."

Q3. Join Fetch vs Join

Entity + configuration

import jakarta.persistence.*;

@Entity
@Table(name = "employees")
public class Employee {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false, length = 60)
    private String name;

    @ManyToOne(fetch = FetchType.LAZY)          // LAZY avoids loading dept eagerly
    @JoinColumn(name = "dept_id")
    private Department dept;

    // Hibernate needs a no-arg constructor
    public Employee() {}
    public Employee(String name) { this.name = name; }
    // getters and setters...
}

Session: persist, get, update, delete

import org.hibernate.*;
import org.hibernate.cfg.Configuration;

class Demo {
    public static void main(String[] args) {
        SessionFactory factory = new Configuration().configure("hibernate.cfg.xml")
                .addAnnotatedClass(Employee.class)
                .buildSessionFactory();

        try (Session session = factory.openSession()) {
            Transaction tx = session.beginTransaction();

            Employee e = new Employee("Jack");
            session.persist(e);              // INSERT

            tx.commit();
        }

        try (Session session = factory.openSession()) {
            Employee loaded = session.get(Employee.class, 1L);   // SELECT by PK
            session.getTransaction().begin();
            loaded.setName("Jack Updated");  // dirty checking: auto UPDATE
            session.getTransaction().commit();
        }

        factory.close();
    }
}

HQL: query objects, not tables

import org.hibernate.query.Query;
import java.util.List;

List<Employee> highPaid = session.createQuery(
        "FROM Employee e WHERE e.salary > :min ORDER BY e.salary DESC", Employee.class)
        .setParameter("min", 80000)
        .setMaxResults(10)                      // pagination at the query level
        .list();

// Criteria API for dynamic queries
var cb = session.getCriteriaBuilder();
var cq = cb.createQuery(Employee.class);
var root = cq.from(Employee.class);
cq.select(root).where(cb.equal(root.get("dept").get("name"), "IT"));
