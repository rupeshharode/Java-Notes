A Servlet is a server-side Java component used to handle client requests, process data, and generate dynamic responses.

A servlet runs inside a servlet container such as Apache Tomcat.

we need to use web.xml file or @webServlet annotation to map a user request to a specific servlet

servlet provide response using printwriter class

  1. How to create a Servlet?

We can create a servlet by extending either:

GenericServlet – A protocol-independent abstract class.

HttpServlet – A class designed specifically for handling HTTP requests.

Both classes belong to the Servlet API.

  1. Difference between GenericServlet and HttpServlet

GenericServlet HttpServlet

Protocol-independent Designed for HTTP

Provides the service() method Provides doGet(), doPost(), doPut(), doDelete(), etc.

We override service() to handle requests We typically override HTTP-specific methods

Does not provide HTTP-specific methods Supports HTTP request methods

Important correction: HttpServlet also has a service() method. It dispatches HTTP requests to the appropriate methods, such as doGet() and doPost().

import java.io.; import jakarta.servlet.;

public class MyServlet extends GenericServlet {

@Override
public void service(ServletRequest req,
                    ServletResponse res)
                    throws IOException {

    res.setContentType("text/plain");

    PrintWriter out = res.getWriter();
    out.println("Hello from GenericServlet");
}

}

import java.io.; import jakarta.servlet.; import jakarta.servlet.http.*; import jakarta.servlet.annotation.WebServlet;

@WebServlet("/hello") public class MyServlet extends HttpServlet {

@Override

                     HttpServletResponse res)
                     throws IOException {

    res.setContentType("text/plain");

}

  1. Difference between RequestDispatcher and sendRedirect()

This is a very common interview question.

RequestDispatcher.forward() sendRedirect()

Works on the server side Sends a redirect response to the browser

Does not change the browser URL Changes the browser URL

Uses the same request and response Creates a new request

Generally faster Requires an additional browser request

RequestDispatcher is used to forward a request from one servlet to another servlet or resource on the server. When we use RequestDispatcher, the browser does not know that the request has been forwarded to another servlet because the URL in the browser remains unchanged.

whereas in senRedirect() browser url is change and need new request from browser Example:

// Forward request.getRequestDispatcher("home.jsp") .forward(request, response);

// Redirect response.sendRedirect("home.jsp");

  1. Session Management

HTTP is a stateless protocol, meaning the server does not automatically remember previous requests from the same client.

Servlets provide session management mechanisms:

HttpSession – Stores user-specific data across requests.

Cookies – Store small pieces of data in the browser.

URL rewriting – Adds session information to a URL when needed.

Hidden form fields – Carry data between form submissions.

Example:

HttpSession session = request.getSession(); session.setAttribute("username", "Jack");

String name = (String) session.getAttribute("username");

Interview question: Why do we use HttpSession?

Answer: To maintain user-specific information across multiple HTTP requests, such as login details.

  1. Servlet Filters

A Filter is used to intercept requests and responses before or after they reach a servlet.

Common uses:

Authentication and authorization.

Logging.

Request validation.

Setting response headers.

Example use case: Checking whether a user is logged in before allowing access to a protected page.

A minimal HttpServlet

import jakarta.servlet.http.*;
import jakarta.servlet.annotation.WebServlet;
import java.io.IOException;

@WebServlet("/hello")   // maps the URL /hello to this servlet
public class HelloServlet extends HttpServlet {

    @Override
    protected void doGet(HttpServletRequest req, HttpServletResponse resp)
            throws IOException {
        resp.setContentType("text/html");
        resp.getWriter().println("<h1>Hello from a Servlet</h1>");
    }

    @Override
    protected void doPost(HttpServletRequest req, HttpServletResponse resp)
            throws IOException {
        String name = req.getParameter("name");   // form data
        resp.getWriter().println("Posted: " + name);
    }
}

The servlet lifecycle

import jakarta.servlet.http.*;
import jakarta.servlet.annotation.WebServlet;

@WebServlet(value = "/life", loadOnStartup = 1)
public class LifeServlet extends HttpServlet {

    @Override public void init() {                 // once, at startup
        System.out.println("init — one instance created");
    }

    @Override protected void service(HttpServletRequest req, HttpServletResponse resp) {
        // called per request; dispatches to doGet/doPost/...
        System.out.println("service — thread per request");
    }

    @Override public void destroy() {              // once, at shutdown
        System.out.println("destroy — cleanup");
    }
}

Init parameters and config

import jakarta.servlet.http.*;
import jakarta.servlet.annotation.WebServlet;
import jakarta.servlet.ServletConfig;

@WebServlet(urlPatterns = "/config", initParams = {
        @WebInitParam(name = "env", value = "prod")
})
public class ConfigServlet extends HttpServlet {
    @Override public void init(ServletConfig config) {
        String env = config.getInitParameter("env");   // "prod"
        System.out.println("env = " + env);
    }
}

ServletContext and request dispatch

import jakarta.servlet.http.*;
import jakarta.servlet.ServletException;
import jakarta.servlet.RequestDispatcher;

class DispatchServlet extends HttpServlet {
    @Override protected void doGet(HttpServletRequest req, HttpServletResponse resp)
            throws ServletException, java.io.IOException {

        req.setAttribute("user", "Jack");                        // request scope

        RequestDispatcher rd = req.getRequestDispatcher("/view.jsp");
        rd.forward(req, resp);       // same request continues server-side
        // resp.sendRedirect("/login");  // vs redirect: new browser request
    }
}
