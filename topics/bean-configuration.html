Q.1 ConfigurableApplicationContext vs ApplicationContext vs BeanFactory?

ConfigurableApplicationContext is an interface in Spring that extends ApplicationContext and provides additional methods to configure and control the lifecycle of the Spring application context.

It provides methods such as refresh(), close(), start(), stop(), and isActive().

For example, close() is used to shut down the Spring container and trigger the destruction callbacks of beans.

AnnotationConfigApplicationContext is one of the implementations of ConfigurableApplicationContext.

*BeanFactory -> BeanFactory is the basic IoC container interface in Spring. It is responsible for creating, configuring, managing, and providing Spring Beans.

It supports dependency injection, bean lifecycle management, and different bean scopes. We can retrieve a bean from the container using the getBean() method.

*ApplicationContext-> extendsBeanFactoryand provides additional features such as event publishing, internationalization, and automatic detection of components. Therefore,ApplicationContextis generally preferred overBeanFactory` in modern Spring applications.

Q.2 Stereotype annotation

@Component is a general-purpose stereotype annotation used to mark a class as a Spring-managed bean. During component scanning, Spring detects the class and creates and manages its bean.

@Service is a specialized form of @Component. It is generally used to indicate that a class contains business logic or service-layer logic.

@Repository is also a specialized form of @Component. It is generally used for the persistence or data-access layer, where the class interacts with the database. In addition, Spring can apply exception translation to certain persistence exceptions and convert them into Spring's DataAccessException hierarchy.

@Controller is a specialized form of @Component used in the Spring MVC presentation layer. It is used to handle web requests and map requests to handler methods, typically using annotations such as @RequestMapping, @GetMapping, and @PostMapping.

We use @Service instead of @Component when we want to clearly communicate that the class belongs to the service layer and contains business logic. Similarly, @Repository communicates that the class belongs to the data-access layer.

Technically, we can use @Component instead of @Service or @Repository for component scanning and bean creation, but we would lose the specific semantic meaning and some specialized behavior, such as repository exception translation.

Q.3 @configuration , @Bean , @componentScan

@Configuration is a class-level annotation used to indicate that a class contains configuration metadata for the Spring IoC container. It is commonly used to define and configure Spring Beans using @Bean methods.

@Bean is a method-level annotation used to declare a bean explicitly. Spring invokes the annotated method and registers the object returned by that method as a Spring-managed bean.

For example:

@Configuration
public class AppConfig {

    @Bean
    public UserRepository userRepository() {
        return new UserRepository();
    }

    @Bean
    public UserService userService() {
        return new UserService(userRepository());
    }
}

Here, AppConfig provides configuration metadata to Spring, and the objects returned by the @Bean methods are registered and managed as Spring Beans.

@Configuration is itself a specialized form of @Component, so the configuration class can also be registered as a Spring bean. However, their purposes are different. @Configuration is used to define configuration and bean definitions, whereas @Component is used to mark a class as a Spring-managed component.

There are three common approaches to configuring Spring applications:

1. Java-based configuration:
We use Java classes with annotations such as @Configuration and @Bean. Bean objects can be instantiated using the new keyword, and Spring manages the returned objects.

2. XML-based configuration:
We define beans and their configuration in an XML file using elements such as <beans> and <bean>. Attributes or elements such as id, class, scope, constructor-arg, and property can be used to configure beans.

3. Annotation-based configuration:
We use annotations such as @Component, @Service, @Repository, @Controller, @ComponentScan, and @Autowired. Spring detects the annotated classes through component scanning and manages their beans.

Component scanning means Spring scans the specified packages for classes annotated with stereotype annotations such as @Component, @Service, @Repository, and @Controller.

For example:

@Configuration
@ComponentScan("com.example.service")
public class AppConfig {
}

Spring scans the specified package and its subpackages for eligible components. If a component is outside the scanned packages, it will not be discovered through that component scan. However, it can still be registered as a bean through other mechanisms, such as an explicit @Bean method.

Q.4 Bean lifecycle , @postconstruct @predestroy, inti destroy method, Initilizingbean , desposablebean

The Spring Bean lifecycle starts when the IoC container is initialized. Spring reads the configuration metadata and creates or registers BeanDefinitions. Based on these definitions, Spring creates the bean instance and resolves its dependencies.

In the case of constructor injection, dependencies are resolved while the bean is being instantiated because they are required by the constructor. In setter or field injection, the bean is instantiated first and then the dependencies are injected.

After dependency injection, Spring calls the appropriate Aware interface callbacks if the bean implements any Aware interface. Then the bean goes through its initialization phase, which can include BeanPostProcessor callbacks and initialization callbacks. After initialization is complete, the bean is ready to be used by the application.

@PostConstruct is a method-level annotation used for an initialization callback. The annotated method is called after dependency injection and before the bean is ready for use.

InitializingBean is an interface that provides the afterPropertiesSet() method. Spring calls this method during the bean's initialization phase after the bean's properties have been set.

Similarly, @PreDestroy is a method-level annotation used for a destruction callback. The annotated method is called when the container is shutting down, before the bean is destroyed.

DisposableBean is an interface that provides the destroy() method, which Spring calls during the destruction phase.

We can also define custom initialization and destruction methods using initMethod and destroyMethod with the @Bean annotation:

@Bean(initMethod = "init", destroyMethod = "cleanup")
public UserService userService() {
    return new UserService();
}

Therefore, the simplified Spring Bean lifecycle is:

Container startup → Configuration metadata → BeanDefinitions → Bean instantiation → Dependency injection → Aware callbacks → Initialization → Bean ready → Container shutdown → Destruction callbacks → Bean destroyed. ```

One interview detail to remember

If the interviewer asks "When exactly is @PostConstruct called?", answer:

"@PostConstruct is called after dependency injection has been completed and before the bean is made available for normal use."

And for @PreDestroy:

"@PreDestroy is called during container shutdown, before the bean is destroyed."

Stereotype annotations

@Component                       // generic bean
class PlainWorker {}

@Service                         // business layer (semantic alias)
class OrderService {}

@Repository                      // data layer + translates DB exceptions
class OrderRepository {}

@Controller                      // web layer (view MVC)
class ProductPageController {}

@RestController                  // @Controller + @ResponseBody (JSON APIs)
class ProductApiController {}

@Configuration + @Bean: Java-based configuration

@Configuration
@ComponentScan("com.jack.app")   // where to look for stereotypes
public class AppConfig {

    @Bean                        // factory method — perfect for 3rd-party classes
    public ObjectMapper objectMapper() {
        return new ObjectMapper().registerModule(new JavaTimeModule());
    }

    @Bean
    public DataSource dataSource() {
        HikariConfig cfg = new HikariConfig();
        cfg.setJdbcUrl("jdbc:postgresql://localhost:5432/app");
        return new HikariDataSource(cfg);
    }
}

@Scope and @Lazy

@Configuration
class Scopes {
    @Bean
    @Scope("singleton")                       // default: one per container
    public ConfigHolder configHolder() { return new ConfigHolder(); }

    @Bean
    @Scope("prototype")                       // new instance per request
    public TaskBuilder taskBuilder() { return new TaskBuilder(); }

    @Bean
    @Lazy                                     // created on first use, not at startup
    public HeavyService heavyService() { return new HeavyService(); }
}

Choosing between styles

// Own application classes  -> @Component stereotypes (scanned automatically)
// Third-party classes      -> @Bean methods in @Configuration
// Legacy system            -> XML (or keep it for the interview question)
// The three can be mixed; constructor injection ties them together.
