Has-a vs Is-a Relationships

Composition vs inheritance — when to prefer which and why.

oopcompositionaggregation

** Has-a & Is-a

IS-A Relationship

An IS-A relationship represents an inheritance relationship where a child class is a specialized type of the parent class.

For example:

Dog IS-A Animal

class Animal { void eat() { System.out.println("Animal eats"); } }

class Dog extends Animal { void bark() { System.out.println("Dog barks"); } }

Here, Dog inherits from Animal.

Animal ↑ Dog

Because Dog is tightly connected to the Animal class through inheritance, changes to the parent class can potentially affect the child class.

IS-A → Inheritance → extends

HAS-A Relationship

A HAS-A relationship represents a relationship where one class contains or uses an object of another class.

For example:

Car HAS-A Engine

class Engine { void start() { System.out.println("Engine starts"); } }

class Car { Engine engine = new Engine();

void startCar() {
    engine.start();
    System.out.println("Car starts");
}

}

Here, Car has an Engine object.

Car ↓ Engine

There is no inheritance between Car and Engine. The relationship is created through object composition/aggregation.

HAS-A → Composition/Aggregation → Object reference

Easy way to remember

IS-A → "What is it?" → Inheritance

Dog IS-A Animal

Car IS-A Vehicle

HAS-A → "What does it contain/have?" → Composition/Aggregation

Car HAS-A Engine

House HAS-A Room

Library HAS-A Book

Composition In composition, one object is an integral part of another.

For example, a House has Rooms. If the house is considered destroyed, its rooms don't meaningfully exist as rooms of that house.

class House { private Room room = new Room(); }

Conceptually:

House ◆──── Room

The House strongly owns the Room.

Aggregation In aggregation, one object contains or uses another object, but that object can exist independently.

For example, a Department has Teachers. A teacher can exist even if that particular department is removed and could move to another department.

class Department { private Teacher teacher;

Department(Teacher teacher) {
    this.teacher = teacher;
}

}

Is-a: inheritance. Has-a: composition.

// IS-A: a Car "is a" Vehicle — inheritance
class Vehicle {
    void start() { System.out.println("Starting engine"); }
}

class Car extends Vehicle { }        // Car IS-A Vehicle

// HAS-A: an Engine "is part of" a Car — composition/aggregation
class Engine {
    void ignite() { System.out.println("Engine ignited"); }
}

class ModernCar {
    private final Engine engine = new Engine();   // ModernCar HAS-A Engine
    void drive() { engine.ignite(); }
}

Aggregation vs composition

import java.util.List;

// Aggregation — the parts can exist without the whole (weak ownership)
class Department {
    private final List<Teacher> teachers;
    Department(List<Teacher> teachers) { this.teachers = teachers; }
    // Teacher objects live on even if the Department is deleted
}

// Composition — the parts die with the whole (strong ownership)
class House {
    private final Room room = new Room();   // Room has no life outside House
}

class Room { }
class Teacher { }

Why composition is usually preferred ("favor composition over inheritance")

// Inheritance locks you into one hierarchy and exposes parent internals.
// Composition lets you swap behaviour at runtime:

interface FlyBehaviour { void fly(); }
class JetEngine implements FlyBehaviour {
    public void fly() { System.out.println("Jet flight"); }
}
class Wings implements FlyBehaviour {
    public void fly() { System.out.println("Flap flap"); }
}

class Bird {
    private FlyBehaviour behaviour;              // injectable
    Bird(FlyBehaviour behaviour) { this.behaviour = behaviour; }
    void performFly() { behaviour.fly(); }
}

class Demo {
    public static void main(String[] args) {
        new Bird(new Wings()).performFly();      // Flap flap
        new Bird(new JetEngine()).performFly();  // Jet flight
    }
}
