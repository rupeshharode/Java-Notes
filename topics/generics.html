Generics

Type-safe classes and methods, bounded types and wildcards.

genericswildcards

Generics were introduced in Java 5 to provide type safety at compile time. They eliminate the need for explicit type casting in many situations and help prevent ClassCastException. Generics allow us to use the same class, interface, or method with different data types. We specify the type parameter using angle brackets (<>).

For example:

ArrayList arr1 = new ArrayList<>(); ArrayList arr2 = new ArrayList<>();

Here, Integer and String are the type arguments. ArrayList is the same generic class, but it can work with different types.

PECS = Producer Extends, Consumer Super

  1. Producer → extends If you are reading/getting data from a generic collection, it is a producer.

List<? extends Number> list

You can safely read Number values from it.

Number n = list.get(0);

But you generally cannot add a Number to it because the exact subtype is unknown.

  1. Consumer → super If you are adding/putting data into a generic collection, it is a consumer.

List<? super Integer> list

You can safely add Integer values:

list.add(10); list.add(20);

|| IMPORTANT ||

? → Unknown type ? extends Number → Number or child → READ ? super Integer → Integer or parent → WRITE

PECS: Producer → Extends Consumer → Super

|| ||

Java implements generics using type erasure. Generic type information is primarily used by the compiler for compile-time type checking, and the type parameters are erased from much of the generated bytecode. Type erasure was designed to preserve backward compatibility with existing non-generic Java code and libraries when generics were introduced in Java 5. or Collections in Java 2"

A generic class

public class Box<T> {
    private T value;

    public void set(T value) { this.value = value; }
    public T get() { return value; }

    public static void main(String[] args) {
        Box<String> words = new Box<>();
        words.set("hello");
        String s = words.get();        // no cast needed — that's the point

        // Box<Integer> box = words;  // compile error: types must match
    }
}

Bounded type parameters

// T must be Number or a subclass — so .doubleValue() is guaranteed
class Stats<T extends Number> {
    private final T[] items;

    Stats(T[] items) { this.items = items; }

    double average() {
        double sum = 0;
        for (T item : items) sum += item.doubleValue();
        return sum / items.length;
    }
}

class Demo {
    public static void main(String[] args) {
        System.out.println(new Stats<>(new Integer[]{1, 2, 3}).average()); // 2.0
        // new Stats<>(new String[]{"a"})   // error: String is not a Number
    }
}

Wildcards: ? extends, ? super, ?

import java.util.*;

class Wildcards {
    // Producer — reads from the list (PECS: Producer Extends)
    static double sum(List<? extends Number> numbers) {
        double total = 0;
        for (Number n : numbers) total += n.doubleValue();
        // numbers.add(1);  // not allowed: compiler can't verify the type
        return total;
    }

    // Consumer — writes into the list (PECS: Consumer Super)
    static void fill(List<? super Integer> sink) {
        sink.add(1);
        sink.add(2);
    }

    public static void main(String[] args) {
        System.out.println(sum(List.of(1, 2.5, 3)));   // ints and doubles both fine
        fill(new ArrayList<Number>());                  // Integer goes into Number
    }
}

Generic methods and type erasure

import java.util.*;

class Util {
    static <K, V> Map<K, V> pair(K key, V value) {
        Map<K, V> map = new HashMap<>();
        map.put(key, value);
        return map;
    }

    static <T extends Comparable<T>> T max(List<T> items) {
        T best = items.get(0);
        for (T item : items) if (item.compareTo(best) > 0) best = item;
        return best;
    }

    public static void main(String[] args) {
        System.out.println(max(List.of("pear", "apple", "fig"))); // pear
    }
}

// Type erasure: generics exist only at compile time.
// List<String> and List<Integer> are both just List at runtime.
// That's why new T[] and instanceof List<String> are illegal.
