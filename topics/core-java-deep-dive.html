explain methods/function?

What is a Method in Java?

In Java, we generally use the term method instead of function because Java organizes executable code inside classes and interfaces.

A method is a block of code that performs a specific task. Once we define a method, we can call it whenever we need that task instead of writing the same code again and again.

Therefore, methods provide code reusability, and they also make the program easier to read, maintain, and understand.

For example:

class Calculator {

int add(int a, int b) {
    return a + b;
}

}

Here, add() is a method that performs the addition of two numbers.

Four Types of Methods Based on Parameters and Return Value

Methods can commonly be classified into four types based on whether they take parameters and whether they return a value:

No parameter and no return value

void greet() { System.out.println("Hello"); }

No parameter but returns a value

int getNumber() { return 10; }

Takes parameters but does not return a value

void printNumber(int n) { System.out.println(n); }

Takes parameters and returns a value

int add(int a, int b) { return a + b; }

In simple words:

Take nothing means the method does not accept parameters.

Take something means the method accepts parameters.

Return nothing means the return type is void.

Return something means the method returns a value.

Methods Based on Modifiers

Methods can also be discussed based on the modifiers or characteristics used with them. Some important ones are:

Instance method — associated with an object and normally called using an object.

Static method — belongs to the class and can be called using the class name.

Final method — cannot be overridden by a subclass.

Abstract method — declared without a method body and implemented by a concrete subclass.

Synchronized method — used for controlling access to a method when multiple threads are involved.

Native method — implemented using native code outside Java, commonly through JNI.

For example:

class Demo {

static void show() {
    System.out.println("Hello");
}

}

Here, show() is a static method, so we can call it using:

Demo.show();

Interview Answer in Short

If the interviewer asks, "What is a method in Java?", I would answer:

"A method in Java is a block of code that performs a specific task. We define a method once and can call it multiple times whenever required, which provides code reusability and improves maintainability. Methods can be classified based on parameters and return values into four common categories: no parameter and no return value, no parameter with a return value, parameters with no return value, and parameters with a return value. Methods can also have modifiers such as static, final, abstract, synchronized, and native."

explain array?

What is an Array in Java?

An array is a fixed-size data structure used to store multiple values of the same data type in a single variable.

Once we declare the size of an array, we cannot change its size during runtime.

For example:

int[] numbers = new int[5];

Here, the array can store exactly 5 integer values.

Array elements are stored and accessed using an index. The index starts from 0 and goes up to size - 1.

numbers[0] = 10; numbers[1] = 20; numbers[2] = 30;

So, the first element is stored at index 0, the second at index 1, and so on.

In Java, an array is an object, and its elements are stored in a logically contiguous sequence of array slots. The important point for an interview is that arrays provide constant-time index-based access.

Interview Answer

"An array in Java is a fixed-size data structure used to store multiple values of the same data type in a single variable. Once we declare the size of an array, we cannot change its size at runtime. Array elements are accessed using an index, which starts from zero. Arrays are useful when we know the number of elements in advance and want fast index-based access."

explain string ?

What is String in Java?

String is a class in Java that belongs to the java.lang package. It is used to represent a sequence of characters.

String is a very commonly used class in Java.

There are several ways to create a String.

  1. Using String Literal

We can create a String directly using double quotes:

String s = "Hello";

When we create a String using a literal, Java checks the String Constant Pool.

If a String with the same content already exists in the pool, Java reuses that existing String object instead of creating another pooled object.

For example:

String s1 = "Hello"; String s2 = "Hello";

Here, s1 and s2 refer to the same pooled String object.

System.out.println(s1 == s2); // true

  1. Using the new Keyword

We can also create a String using the new keyword:

String s = new String("Hello");

In this case, a new String object is explicitly created.

For example:

String s1 = new String("Hello"); String s2 = new String("Hello");

Here, s1 and s2 refer to different String objects.

System.out.println(s1 == s2); // false

However, both objects contain the same text, so:

System.out.println(s1.equals(s2)); // true

This is an important interview point:

== compares object references.

equals() compares the content of the Strings.

  1. Creating String from Character or Byte Arrays

We can also create a String from a character array:

char[] arr = {'H', 'e', 'l', 'l', 'o'}; String s = new String(arr);

We can also create a String from a byte array:

byte[] arr = {65, 66, 67}; String s = new String(arr);

The result is "ABC" because 65, 66, and 67 represent those characters in the relevant character encoding.

String is Immutable

Another very important property of String is that String objects are immutable.

It means once a String object is created, its content cannot be changed.

For example:

String s = "Hello"; s.concat(" World");

System.out.println(s); // Hello

concat() does not modify the original String. It creates a new String.

If we write:

s = s.concat(" World");

then s refers to the newly created String "Hello World".

Common String Methods

Java provides many useful methods for working with Strings, such as:

length() — returns the length of the String.

charAt() — returns the character at a particular index.

indexOf() — returns the index of a character or substring.

toUpperCase() — converts the String to uppercase.

toLowerCase() — converts the String to lowercase.

contains() — checks whether a particular sequence exists.

replace() — replaces characters or sequences.

substring() — extracts a portion of a String.

equals() — compares String contents.

equalsIgnoreCase() — compares contents while ignoring case.

Interview Answer

We can create a String using a String literal, the new keyword, or from character and byte arrays. When we create a String using a literal, Java uses the String Constant Pool and can reuse an existing String with the same content. When we explicitly use new, a new String object is created. String is also immutable, which means its content cannot be changed after the object is created. Java provides many methods such as length(), charAt(), indexOf(), contains(), replace(), substring(), toUpperCase(), and toLowerCase() for String manipulation."

why string is immutable?

String is immutable in Java, meaning once a String object is created, its content cannot be changed.

For example:

String s = "Hello"; s.concat(" World");

System.out.println(s); // Hello

concat() doesn't modify "Hello"; it creates a new String.

Why is String immutable? There are several important reasons:

  1. String Pool Java maintains a String Constant Pool where String literals can be reused.

String s1 = "Hello"; String s2 = "Hello";

Both can refer to the same String object.

If Strings were mutable, changing s1 could unexpectedly change what s2 sees. Immutability makes this sharing safe.

  1. Security Strings are commonly used for sensitive information such as:

File paths

Database URLs

Class names

Network connections

Authentication-related information

If a String could change after it was passed to a security-sensitive operation, it could create security problems.

  1. Thread Safety Because a String cannot be changed after creation, the same String object can safely be shared between multiple threads without synchronization just to protect its contents.

  2. HashCode and HashMap Strings are frequently used as keys in collections such as HashMap.

Map map = new HashMap<>(); map.put("Java", 100);

If a String used as a key could change after insertion, its hashCode() could change, making the entry difficult or impossible to find in the expected bucket.

Immutability prevents this problem.

Interview Answer "String is immutable in Java, which means once a String object is created, its content cannot be changed. The main reasons for String immutability are safe sharing through the String Pool, security, thread safety, and reliable use as keys in hash-based collections like HashMap. Whenever we perform an operation that appears to modify a String, Java actually creates a new String object instead of modifying the existing one."

Easy way to remember String immutable → Safe sharing + Security + Thread safety + HashMap reliability.

A BufferedReader maintains a character buffer in memory.

Instead of your program asking the underlying input source for every single character, BufferedReader reads a chunk of characters at once and stores them in its internal buffer.

For example, imagine the user enters:

Hello World

Conceptually:

Input source ┌──────────────────────────┐ │ H e l l o W o r l d \n │ └──────────────────────────┘ ↓ BufferedReader ┌───────────────┐ Buffer│ H e l l o ... │ └───────────────┘ ↓ readLine() ↓ "Hello World"

When your program calls readLine() or read(), BufferedReader gets the required characters from its buffer.

If the buffer doesn't have enough data, it goes back to the underlying Reader, reads another chunk, and fills the buffer again.

Why is buffering useful? Reading from an input source can be relatively expensive. If we repeatedly access the underlying source for every character, there can be many I/O operations.

Buffering reduces the number of such underlying reads.

So the basic idea is:

Read a larger chunk → store it in memory → serve smaller reads from the buffer.

difference between == and .equals?

== vs equals() in Java

Both == and equals() can be used when comparing objects, but they work differently.

== Operator

When we use == with objects, it compares their references, meaning it checks whether both reference variables point to the same object in memory.

String s1 = new String("Hello"); String s2 = new String("Hello");

System.out.println(s1 == s2); // false

Here, s1 and s2 contain the same text, but they refer to different objects. Therefore, == returns false.

equals() Method

equals() is a method defined in the Object class.

The default implementation provided by Object essentially compares object identity, but classes can override equals() to provide their own definition of logical equality.

For example, String overrides equals() to compare the content of two strings.

String s1 = new String("Hello"); String s2 = new String("Hello");

System.out.println(s1.equals(s2)); // true

Here, both Strings contain the same content, so String's overridden equals() method returns true.

Wrapper classes such as Integer, Double, and Boolean also override equals() to compare their values.

Main Difference == equals() Operator Method For objects, compares references Can compare logical/content equality Cannot be overridden Can be overridden Checks whether two references point to the same object Depends on the class's implementation Works with primitives as value comparison Used with objects Important Example String s1 = "Hello"; String s2 = "Hello";

System.out.println(s1 == s2); // true System.out.println(s1.equals(s2)); // true

== is true here because String literals with the same content can refer to the same object in the String Pool.

But:

String s1 = new String("Hello"); String s2 = new String("Hello");

System.out.println(s1 == s2); // false System.out.println(s1.equals(s2)); // true

Here, new creates separate String objects, so their references are different, while their contents are equal.

Interview Answer

"== and equals() are used differently for object comparison. When used with objects, == compares references and checks whether two references point to the same object. equals() is a method defined in the Object class. The default Object implementation compares object identity, but classes such as String and wrapper classes override equals() to compare their logical values or contents. Therefore, for objects, we generally use equals() when we want to compare their logical content."

how many modifiers we can use with main method?

Modifiers of the main() Method

In Java, the main() method is commonly written as:

public static void main(String[] args) { // code }

The main() method can be declared with certain modifiers. Commonly discussed modifiers include:

public

static

final

synchronized

strictfp

  1. public

public allows the JVM to access the main() method from outside the class.

public static void main(String[] args)

Without appropriate accessibility, the JVM cannot use the method as the program's entry point.

  1. static

static means the method belongs to the class rather than to an object.

The JVM can invoke main() without creating an object of the class.

public static void main(String[] args)

  1. final

final means the method cannot be overridden by a subclass.

public static final void main(String[] args) { }

It is valid to declare main() as final, although it is not normally necessary.

  1. synchronized

synchronized can be used to make access to the method synchronized.

public static synchronized void main(String[] args) { }

This means that when the method is invoked, the JVM applies Java's synchronization mechanism to the class object's monitor for a static synchronized method.

It is valid, but normally there is no practical need to make main() synchronized.

  1. strictfp

strictfp was used to require strict IEEE 754 floating-point behavior for calculations performed in a method or class.

The purpose was to make floating-point calculations more consistent across different platforms.

However, important modern-Java point: since Java 17, floating-point expressions are always strict, so strictfp is no longer necessary and is deprecated for removal.

Interview Answer

"The main() method is commonly declared using public and static modifiers. Other modifiers such as final, synchronized, and historically strictfp can also be used in certain declarations. Public allows the JVM to access the method, static allows the JVM to invoke it without creating an object, final prevents overriding, and synchronized applies synchronization. strictfp was used to enforce strict IEEE 754 floating-point behavior, but since Java 17, floating-point expressions are strict by default, so strictfp is no longer needed."

why this/super keywords is used?

What is this Keyword in Java?

this is a reference variable in Java that refers to the current object.

It is mainly used inside instance methods and constructors when we want to refer to the current object's instance variables, methods, or constructor.

  1. To differentiate between instance variables and local variables

If an instance variable and a local variable or parameter have the same name, we use this to refer to the instance variable.

class Student {

int age;

Student(int age) {
    this.age = age;
}

}

Here, both variables are named age.

this.age → instance variable age → constructor parameter

So:

this.age = age;

means:

Assign the value of the parameter age to the current object's instance variable age.

  1. To call the current object's method

We can use this to call an instance method of the current object.

class Student {

void display() {
    System.out.println("Hello");
}

void show() {
    this.display();
}

}

Here, this.display() means calling the display() method of the current object.

  1. To call another constructor of the same class

this() can be used to call another constructor of the same class.

class Student {

Student() {
    this(20);
}

Student(int age) {
    System.out.println(age);
}

}

Here, this(20) calls the parameterized constructor of the same class.

Important Difference

Don't confuse:

this

with:

this()

this → refers to the current object.

this() → calls another constructor of the same class.

Interview Answer

"this is a reference variable in Java that refers to the current object. It is mainly used inside instance methods and constructors. One common use is to differentiate between an instance variable and a local variable or parameter when they have the same name. For example, this.age = age means assigning the parameter age to the current object's instance variable age. It can also be used to call the current object's methods and to call another constructor of the same class using this()."

What is super Keyword in Java?

super is a keyword in Java that is used inside a child class (subclass) to refer to its immediate parent class (superclass).

We mainly use super when we want to access the parent class's variables, methods, or constructors.

  1. Access Parent Class Variable

If the parent and child class have instance variables with the same name, we can use super to access the parent variable.

class Parent { int x = 10; }

class Child extends Parent { int x = 20;

void display() {
    System.out.println(super.x);
}

}

Here:

x → Child class variable super.x → Parent class variable

  1. Call Parent Class Method

If a child class overrides a parent method and we want to call the parent version of that method, we use super.

class Parent { void display() { System.out.println("Parent method"); } }

class Child extends Parent {

@Override
void display() {
    System.out.println("Child method");
    super.display();
}

}

Output:

Child method Parent method

Here, super.display() calls the parent class's method.

  1. Call Parent Class Constructor

We can use super() to call the constructor of the immediate parent class.

class Parent {

Parent() {
    System.out.println("Parent constructor");
}

}

class Child extends Parent {

Child() {
    super();
    System.out.println("Child constructor");
}

}

When we create a Child object, the parent constructor executes first, followed by the child constructor.

Parent constructor Child constructor

If we don't explicitly write super() in a child constructor, Java implicitly inserts a call to the no-argument parent constructor, provided that such a constructor is accessible.

Important Difference

Don't confuse this and super:

this → current class/current object super → immediate parent class

For example:

this.x // current class's variable super.x // parent class's variable

this() // another constructor of same class super() // constructor of parent class

Interview Answer

"super is a keyword in Java that is used inside a child class to refer to its immediate parent class. We mainly use it to access the parent class's variables, call the parent class's overridden methods, and invoke the parent class's constructor. For example, super.x accesses the parent variable, super.display() calls the parent method, and super() calls the parent constructor."

types of variables in java ?

Types of Variables in Java

There are three main types of variables in Java:

Local variables

Instance variables

Static variables

  1. Local Variable

A local variable is declared inside a method, constructor, or block.

Its scope is limited to that particular method, constructor, or block.

class Student {

void display() {
    int age = 20;  // local variable
    System.out.println(age);
}

}

Here, age is a local variable because it is declared inside the display() method.

A local variable is created when the method/block is executed and cannot be accessed outside its scope.

  1. Instance Variable

An instance variable is a variable declared inside a class but outside methods, constructors, and blocks, and it is not declared static.

An instance variable is associated with an object. Each object gets its own copy.

class Student {

int age;  // instance variable

}

For example:

Student s1 = new Student(); Student s2 = new Student();

s1.age = 20; s2.age = 25;

Here, s1 and s2 have their own separate age variables.

  1. Static Variable

A static variable is declared inside a class using the static keyword.

It belongs to the class, rather than to individual objects.

class Student {

static String college = "ABC College";

}

All objects can share the same static variable:

Student s1 = new Student(); Student s2 = new Student();

System.out.println(Student.college);

There is generally one class-level copy of a static field for that class, rather than one copy per object.

An instance variable is declared inside a class but outside methods and is associated with an object, so each object generally has its own copy. A static variable is declared using the static keyword and belongs to the class, so it is shared among the objects of that class."

String immutability and the pool

public class Strings {
    public static void main(String[] args) {
        String a = "java";                  // interned in the String pool
        String b = new String("java");      // new object on the heap
        String c = b.intern();              // returns the pooled instance

        System.out.println(a == b);         // false
        System.out.println(a == c);         // true
        System.out.println(a.equals(b));    // true

        // Immutability makes String thread-safe and hash-key safe
        String s = "jack";
        s.toUpperCase();                    // new String returned, s unchanged
        System.out.println(s);              // jack
    }
}

Writing an immutable class by hand

import java.util.*;

public final class Config {                    // 1. final class: no subclassing
    private final String name;
    private final List<String> hosts;

    public Config(String name, List<String> hosts) {
        this.name = name;
        this.hosts = List.copyOf(hosts);       // 2. defensive copy on the way IN
    }

    public String name() { return name; }

    public List<String> hosts() {
        return hosts;                          // 3. List.copyOf is unmodifiable
    }
}

        case Circle c -> Math.PI * c.r() * c.r();
        case Square sq -> sq.side() * sq.side();
        case Triangle t -> 0.5 * t.base() * t.height();
    };
}

// Runtime data areas:
// - Heap: objects live here, shared by all threads, garbage collected

// - Metaspace: class metadata (moved out of the heap since Java 8)
