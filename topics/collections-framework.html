Collections Framework

List, Set, Queue, Map — the hierarchy, implementations and when to use each.

collectionslistmapset

Note :- Map is not a child of collection

“Java Collection Framework is a set of interfaces, classes, and utility methods provided by Java to store and manipulate a group of objects efficiently.

It provides interfaces like List, Set, Queue, and Map, along with their implementations such as ArrayList, LinkedList, HashSet, HashMap, and PriorityQueue.

It also provides utility methods through the Collections class, such as sort(), reverse(), and shuffle().

(or)

The Java Collection Framework provides ready‑made data structures (like lists, sets, maps, and queues) and algorithms (like sorting and searching) to efficiently store, retrieve, and manipulate groups of objects. It saves developers from writing custom data structures

So, basically, the Collection Framework provides ready-made data structures and algorithms that make it easier to store, access, and manipulate collections of objects.”

It provides commonly used interfaces such as:

List – stores ordered elements and allows duplicates.

Set – stores unique elements.

Queue – generally follows FIFO (First In, First Out) order.

Some common implementations are:

ArrayList and LinkedList → implementations of List

HashSet → implementation of Set

PriorityQueue → implementation of Queue

The Collection Framework also provides useful algorithms, such as:

Collections.sort() – sorts elements.

Collections.reverse() – reverses the order of elements.

Collections.shuffle() – randomly rearranges elements.

Iterable │ └── Collection ├── List │ ├── ArrayList │ ├── LinkedList │ └── Vector │ └── Stack │ ├── Set │ ├── HashSet │ │ └── LinkedHashSet │ └── SortedSet │ └── NavigableSet │ └── TreeSet │ └── Queue ├── PriorityQueue └── Deque ├── ArrayDeque └── LinkedList

Map ← separate from Collection │ ├── HashMap │ └── LinkedHashMap │ ├── SortedMap │ └── NavigableMap │ └── TreeMap │ ├── Hashtable │ └── ConcurrentHashMap

Map is part of the Collections Framework, but not part of Collection The Java Collections Framework (JCF) is the overall framework that provides data structures

The hierarchy you should be able to draw

import java.util.*;

// Iterable -> Collection -> { List, Set, Queue }
// Map is separate — NOT a child of Collection

List<String> list = new ArrayList<>();      // fast random access, O(1) get
List<String> linked = new LinkedList<>();   // fast inserts/removes at ends
Set<String> set = new HashSet<>();          // no order, O(1) contains
Set<String> sorted = new TreeSet<>();       // sorted order, O(log n)
Set<String> ordered = new LinkedHashSet<>();// insertion order kept
Queue<String> pq = new PriorityQueue<>();   // natural ordering, heap-backed
Map<String, Integer> map = new HashMap<>(); // O(1) put/get, no order
Map<String, Integer> treeMap = new TreeMap<>(); // sorted by key

ArrayList vs LinkedList in action

import java.util.*;

class Demo {
    public static void main(String[] args) {
        List<String> names = new ArrayList<>();
        names.add("Jack");            // append: O(1) amortized
        names.add("Riya");
        names.set(0, "John");         // replace by index: O(1)
        names.remove(1);              // shift elements: O(n)
        System.out.println(names);    // [John]

        // Fail-fast iteration: modifying while iterating throws
        // ConcurrentModificationException
        for (String n : List.of("a", "b", "c")) {
            // names.add(n);  // would blow up on the next next() call
        }
    }
}

HashMap: put, get, and the entrySet loop

import java.util.*;

class Frequency {
    public static void main(String[] args) {
        Map<String, Integer> count = new HashMap<>();
        for (String word : "java is fun and java is vast".split(" ")) {
            count.merge(word, 1, Integer::sum);   // classic counting idiom
        }

        for (Map.Entry<String, Integer> e : count.entrySet()) {
            System.out.println(e.getKey() + " -> " + e.getValue());
        }

        System.out.println(count.getOrDefault("rust", 0)); // 0, no NPE
    }
}

Choosing between them

// | Need                          | Use                    |
// |-------------------------------|------------------------|
// | Index-based access            | ArrayList              |
// | Many insert/delete at ends    | LinkedList / ArrayDeque|
// | Unique items, fast lookup     | HashSet                |
// | Unique + sorted               | TreeSet                |
// | Key -> value, fast            | HashMap                |
// | Sorted keys                   | TreeMap                |
// | Priority order processing     | PriorityQueue          |
// | Thread-safe                   | ConcurrentHashMap, CopyOnWriteArrayList |
