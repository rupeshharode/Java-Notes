OOPs & Encapsulation

The four pillars of OOP and how encapsulation binds data with behaviour.

oopencapsulationclasses

Object-Oriented Programming (OOP) is a programming approach used to model real-world entities in software.

In OOP, we organize code using classes and objects. A class is a blueprint that defines the properties and behaviors of an entity, while an object is an instance of a class.

OOP has four main pillars:

Encapsulation – Encapsulation means binding data and methods together into a single unit, usually a class. It also helps protect the data by controlling access to it.

Inheritance – Inheritance allows one class to acquire the properties and behaviors of another class, which promotes code reuse.

Polymorphism – Polymorphism allows the same method or interface to behave differently depending on the object or situation.

Abstraction – Abstraction means hiding unnecessary implementation details and showing only the essential information to the user.

Encapsulation

Encapsulation means binding (wrapping) data and the methods that operate on that data into a single unit, usually a class.

It helps protect the data by controlling how it can be accessed or modified from outside the class.

In Java, encapsulation can commonly be achieved by:

Making fields private.

Providing public getter and setter methods when appropriate.

Adding validation or business rules before allowing data to be changed.

Exposing only the operations that are actually needed.

For example, instead of allowing anyone to directly change an employee's salary, we can make salary private and provide a method that validates the new salary before updating it.

So, encapsulation is essentially:

Data + Methods → Single Unit + Controlled Access

Encapsulation with validation — the classic salary example

public class Employee {
    private double salary;   // hidden from the outside world

    public double getSalary() {
        return salary;
    }

    public void setSalary(double salary) {
        if (salary < 0) {                       // business rule enforced here
            throw new IllegalArgumentException("Salary cannot be negative");
        }
        this.salary = salary;
    }
}

The four pillars in one program

// Encapsulation — data + methods in one unit, access controlled
class BankAccount {
    private double balance;

    public void deposit(double amount) { if (amount > 0) balance += amount; }
    public double getBalance() { return balance; }
}

// Inheritance — reuse from a parent class
class SavingsAccount extends BankAccount {
    private double interestRate = 4.5;
}

// Polymorphism — one method name, different behaviour
interface Shape { double area(); }
class Circle implements Shape {
    private final double r;
    Circle(double r) { this.r = r; }
    public double area() { return Math.PI * r * r; }
}
class Square implements Shape {
    private final double side;
    Square(double side) { this.side = side; }
    public double area() { return side * side; }
}

// Abstraction — callers see behaviour, not implementation
class Main {
    public static void main(String[] args) {
        Shape s = new Circle(7);   // depends on the interface, not the class
        System.out.println(s.area());
    }
}

When encapsulation is broken

class BadAccount {
    double balance = 0;   // public field — anyone can set it to 1 crore
}

class Demo {
    public static void main(String[] args) {
        BadAccount bad = new BadAccount();
        bad.balance = -9999;      // no validation possible!
        System.out.println(bad.balance);
    }
}
