Spring MVC

The request flow from DispatcherServlet to view resolution.

springmvccontrollers

DispatcherServlet is the front controller of Spring MVC. It receives incoming HTTP requests and coordinates the request-processing flow.

When a request arrives, DispatcherServlet uses HandlerMapping to find the appropriate controller method. Then HandlerAdapter invokes that method.

The controller generally calls the service layer, and the service layer may communicate with the repository or database.

The simplified request flow is:

Client → Tomcat → DispatcherServlet → HandlerMapping → HandlerAdapter → Controller → Service → Repository → Database.

@Controller is used to mark a class as a Spring MVC controller. @RestController is a combination of @Controller and @ResponseBody, so it is commonly used when controller methods return response data such as JSON.

@RequestMapping is used to map HTTP requests to controller classes or methods. @GetMapping, @PostMapping, @PutMapping, and @DeleteMapping are specialized mappings for different HTTP methods.

@RequestParam is used to retrieve query parameters, such as /users?id=10.

@GetMapping("/users") public User getUser(@RequestParam int id) { // id = 10 }

@PathVariable is used to retrieve values from the URL path, such as /users/10.

@GetMapping("/users/{id}") public User getUser(@PathVariable int id) { // id = 10 }

@RequestBody is used to read data from the HTTP request body and convert it into a Java object, for example, converting JSON into a Java object.

JSON { "name": "Rupesh", "age": 22 }

@PostMapping("/users") public User createUser(@RequestBody User user) { return user; }

What is @ResponseBody?

@ResponseBody tells Spring MVC to write the return value of a controller method directly to the HTTP response body instead of treating it as a view name.

For example, if a controller method returns a User object, Spring can use an HTTP message converter such as Jackson to convert the object into JSON and send it to the client.

@RestController includes @ResponseBody, so we generally don't need to use @ResponseBody separately on every method in a REST controller.. For example: @Controller public class UserController {

@GetMapping("/user")
@ResponseBody
public User getUser() {
    return new User(1, "Rupesh");
}

}

If Jackson is configured, the User object can be converted to JSON: { "id": 1, "name": "Rupesh" }

What is ResponseEntity?

ResponseEntity is a Spring class used to control the complete HTTP response from a controller. It allows us to specify the response body, HTTP status code, and HTTP headers.

For example, ResponseEntity.ok(user) returns a 200 OK response with the user as the response body, while ResponseEntity.notFound().build() returns a 404 Not Found response.

It is useful when we need more control over the HTTP response instead of returning only the response body.

Spring MVC with annotations (what you write today)

import org.springframework.stereotype.Controller;
import org.springframework.web.bind.annotation.*;

@Controller
public class ProductController {

    @GetMapping("/products")                 // maps GET /products
    public String list(org.springframework.ui.Model model) {
        model.addAttribute("products", java.util.List.of("Laptop", "Phone"));
        return "products";                   // view name -> products.jsp / thymeleaf
    }

    @PostMapping("/products")
    public String create(@RequestParam String name) {
        return "redirect:/products";         // redirect after POST
    }
}

REST controller returning JSON

import org.springframework.web.bind.annotation.*;
import org.springframework.http.ResponseEntity;

@RestController                   // @Controller + @ResponseBody
@RequestMapping("/api/products")
public class ProductApiController {

    @GetMapping
    public List<Product> all() {
        return productService.findAll();
    }

    @GetMapping("/{id}")
    public ResponseEntity<Product> one(@PathVariable Long id) {
        return ResponseEntity.ok(productService.findById(id));
    }

    @PostMapping
    public ResponseEntity<Product> create(@RequestBody Product p) {
        return ResponseEntity.status(201).body(productService.save(p));
    }
}

The request flow (know it for interviews)

// 1. Request hits Tomcat (servlet container)
// 2. DispatcherServlet (front controller) receives it
// 3. HandlerMapping finds the matching @Controller method
// 4. HandlerAdapter invokes it (argument resolvers bind params)
// 5. Controller returns a model + view name (or @ResponseBody data)
// 6. ViewResolver picks the template -> view renders
// 7. Response goes back through filters to the client

Form binding and validation

import jakarta.validation.constraints.*;
import org.springframework.web.bind.annotation.*;

record SignupForm(
        @NotBlank String username,
        @Email String email,
        @Min(18) int age) {}

@RestController
class SignupController {
    @PostMapping("/signup")
    String signup(@Valid SignupForm form) {     // @Valid triggers validation
        return "created " + form.username();
    }
}
