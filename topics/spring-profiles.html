Spring Profiles are used to manage environment-specific configurations in a Spring application. For example, in the development environment, we may use a local MySQL database, while in the production environment, we may use a cloud database.

Instead of manually changing configuration values every time we deploy the application, we can create separate property files, such as application-dev.properties and application-prod.properties.

We can activate a profile using the spring.profiles.active property, a command-line argument, or an environment variable.

Spring also provides the @Profile annotation, which allows us to register specific beans or configuration classes only when a particular profile is active.

For example, we might use a dummy notification service during development and an actual notification service in production.

This approach makes configuration management easier and reduces the risk of accidentally using development settings in production.

Examples-> @Service @Profile("dev") public class DummyNotificationService implements NotificationService {

public void sendNotification() {
    System.out.println("Dummy notification");
}

}

@Profile({"dev", "test"}) @Bean public NotificationService notificationService() { return new DummyNotificationService(); }

Spring Boot uses the default profile when no active profile is specified. However, this does not mean that any arbitrary bean will automatically be selected.

  1. What is the Environment interface? The Environment interface belongs to Spring Core. It provides access to the application's properties and environment profiles. It allows us to retrieve configuration values from sources such as: - application.properties - application.yml - Operating-system environment variables - Java system properties - Command-line arguments and other registered property sources It also provides methods to check which profiles are active. Example 1: Reading a property using Environment Suppose your Spring Boot project contains this file: src/main/resources/application.properties app.name=JavaApplication app.version=1.0 app.timeout=30

You want to access these values from a Java class. import org.springframework.core.env.Environment; import org.springframework.stereotype.Component;

@Component public class AppConfig {

private final Environment environment;

public AppConfig(Environment environment) {
    this.environment = environment;
}

public void displayProperties() {

    String name =
            environment.getProperty("app.name");

    String version =
            environment.getProperty("app.version");

    Integer timeout =
            environment.getProperty(
                "app.timeout", Integer.class);

    System.out.println(name);
    System.out.println(version);
    System.out.println(timeout);
}

}

Output: JavaApplication 1.0 30

  1. What is a PropertySource? A PropertySource is an abstraction in Spring that represents one source of configuration properties. Think of each source as a collection of key-value pairs. For example:

application.properties app.name=MyApp

Environment variables APP_NAME=ProductionApp

Java system properties -Dapp.name=TestApp

Each of these sources can provide configuration values. Spring's Environment maintains and queries registered property sources. Example: A custom property source Spring also allows you to register properties from a custom source. One simple way is to use @PropertySource to load a separate properties file. Suppose you create: src/main/resources/custom.properties notification.mode=email notification.retry-count=3

You can register that file like this: @Configuration @PropertySource("classpath:custom.properties")

Activating profiles

// src/main/resources/application.yml
// spring:
//   profiles:
//     active: dev        # or set env var SPRING_PROFILES_ACTIVE=prod

@RestController
class InfoController {
    @Value("${app.greeting:hello}")      // default if the key is missing
    private String greeting;

    @GetMapping("/info")
    String info() { return greeting; }
}

Profile-specific beans

@Configuration
public class DataConfig {

    @Profile("dev")                       // only registered in dev
    @Bean
    public DataSource h2() {
        return new EmbeddedDatabaseBuilder().setType(EmbeddedDatabaseType.H2).build();
    }

    @Profile("prod")
    @Bean
    public DataSource postgres(
            @Value("${db.url}") String url,
            @Value("${db.user}") String user,
            @Value("${db.password}") String password) {
        var cfg = new HikariConfig();
        cfg.setJdbcUrl(url);
        cfg.setUsername(user);
        cfg.setPassword(password);
        return new HikariDataSource(cfg);
    }

    @Bean
    @Profile("!prod")                     // anything except prod
    public FakePaymentGateway fakeGateway() { return new FakePaymentGateway(); }
}
