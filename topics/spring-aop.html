Spring AOP

Aspects, advice types, pointcuts and cross-cutting concerns.

springaopaspects

AOP stands for Aspect-Oriented Programming. It is a programming approach used to separate cross-cutting concerns from the main business logic.

Cross-cutting concerns are functionalities that are required across multiple classes or methods, such as logging, security checks, transaction management, and performance monitoring.

For example, if we want to measure the execution time of multiple service methods, we could write timing logic in every method. This would duplicate code and make the business logic harder to maintain. Using Spring AOP, we can define this logic in a separate aspect and apply it to the required methods.

Spring AOP uses proxies to intercept method calls and execute the required advice around the target method. It commonly uses JDK dynamic proxies or CGLIB-based proxies.

Spring's AOP infrastructure can use BeanPostProcessors to create and return proxy objects for eligible beans during bean initialization.

The main benefit of AOP is that it improves separation of concerns, reduces code duplication, and makes the application easier to maintain.

work flow

Client calls a Spring bean | Proxy intercepts the method call Matches the applicable pointcut | Advice executes For example, logging or a security check | Target method executes | Advice completes and the result returns

The three main AOP terms: Where, When, and What

Term Answers Meaning Pointcut Where? Selects the method executions where advice should apply Advice When and what? Defines the action and when it runs Aspect What is grouped together? Combines pointcut and advice into a reusable concern

What are the main AOP terms?

Term Correct meaning Aspect A module that groups a cross-cutting concern, usually containing advice and pointcuts Join point A point during execution where advice could be applied; Spring AOP supports method-execution join points Pointcut A predicate or expression that selects matching join points Advice The action executed at a selected join point Target object The actual object whose method is being advised Proxy The object through which intercepted calls are handled Weaving The process of connecting aspects with the target program; Spring AOP generally does this through proxies at runtime Cross-cutting concern Functionality used across multiple parts of an application, such as logging or transactions

@Before Runs before the target method executes. @Before("serviceMethods()") public void logBefore() { System.out.println("Before method"); }

@AfterReturning Runs after the target method returns successfully. It can access the returned value. @AfterReturning( pointcut = "serviceMethods()", returning = "result" ) public void logResult(Object result) { System.out.println(result); }

@AfterThrowing Runs when the target method exits by throwing an exception. @AfterThrowing( pointcut = "serviceMethods()", throwing = "ex" ) public void logError(Exception ex) { System.out.println(ex.getMessage()); }

@After Runs after the target method completes, whether it returns normally or throws an exception. It is similar to a finally block. @After("serviceMethods()") public void logCompletion() { System.out.println("Method completed"); }

@Around Provides the greatest control over method execution. It can run logic before and after the target method, decide whether to proceed, and inspect or transform arguments and the returned value. @Around("serviceMethods()") public Object measureTime( ProceedingJoinPoint joinPoint) throws Throwable {

long start = System.currentTimeMillis();

try {
    return joinPoint.proceed();
} finally {
    long end = System.currentTimeMillis();
    System.out.println("Time: " + (end - start));
}

}

Important: @Around can modify method arguments using proceed(args) and transform a compatible return value. It doesn't automatically provide arbitrary access to HTTP requests or responses; those require appropriate objects or framework APIs.

public interface PaymentService { void pay(); }

@Service public class PaymentServiceImpl implements PaymentService {

when JDK proxying is used, the proxy implements PaymentService. You normally access it through the interface: PaymentService service = context.getBean(PaymentService.class); service.pay();

CGLIB proxy example A CGLIB proxy creates a subclass of the target class and overrides eligible methods to add interception behavior. One important nuance: Spring Boot commonly defaults to class-based proxies, while Spring Framework proxy selection depends on configuration. JDK proxies can be used when interface-based proxying is selected.

  1. What is the difference between Spring AOP and AspectJ?

Answer: Spring AOP and AspectJ are used to implement Aspect-Oriented Programming, but they differ in how they apply aspects. Spring AOP AspectJ Primarily uses runtime proxies. Supports compile-time, post-compile, and load-time weaving. Supports method-execution join points. Supports a wider range of join points, including field access and method calls. Works primarily with Spring-managed beans. Can also apply aspects to objects that are not Spring-managed. Easier to configure for common Spring applications. Provides more advanced features and may require additional configuration. Self-invocation bypasses proxy-based advice. Can handle self-invocation when the relevant code is woven.

Example: Spring AOP can be used to log service method executions, while AspectJ can also intercept field access when configured with the appropriate weaving mechanism.

  1. How do you enable AOP in Spring using @EnableAspectJAutoProxy?

Answer: @EnableAspectJAutoProxy enables support for processing @Aspect beans and applying their advice through Spring AOP proxies. Example: @Configuration @EnableAspectJAutoProxy @ComponentScan("com.example") public class AppConfig { }

Here: - @Configuration defines a Spring configuration class. - @EnableAspectJAutoProxy enables proxy-based AOP. - @ComponentScan discovers Spring components, including aspect classes annotated with @Component. In Spring Boot, AOP may be configured automatically when the required dependency is present, so this annotation is not always necessary.

  1. How do you define an aspect using @Aspect and @Component?

Answer: We use @Aspect to declare a class as an aspect and @Component to register it as a Spring bean. Example: @Aspect @Component public class LoggingAspect {

@Before("execution(* com.example.service.*.*(..))")
public void logBefore() {
    System.out.println("Before method execution");
}

}

Here: - @Aspect identifies the class as an aspect. - @Component registers it as a Spring-managed bean. - @Before defines the advice that executes before a matching method. - execution() specifies which method executions should be intercepted.

  1. How do you pass method arguments to advice using args()?

Answer: The args() pointcut designator matches methods based on their runtime argument types. It can also bind method arguments to parameters in the advice method. Example: @Before( value = "execution(* com.example.service..(..)) && args(name)", argNames = "name" ) public void logArgument(String name) { System.out.println("Argument: " + name); }

This advice matches methods in the specified package that have one argument compatible with String and passes that argument to logArgument(). For example, if a matching method receives "Rupesh", the advice prints: Argument: Rupesh

  1. How do you access the return value in @AfterReturning?

Answer: We use the returning attribute of @AfterReturning to access the value returned by a successfully executed target method. Example: @AfterReturning( pointcut = "execution(* com.example.service..(..))", returning = "result" ) public void logResult(Object result) { System.out.println("Returned value: " + result); }

Here, returning = "result" binds the target method's return value to the result parameter. This advice executes only when the target method completes successfully.

  1. How do you access the exception in @AfterThrowing? Answer: We use the throwing attribute of @AfterThrowing to access an exception thrown by the target method. Example: @AfterThrowing( pointcut = "execution(* com.example.service..(..))", throwing = "ex" ) public void logException(Exception ex) { System.out.println("Exception: " + ex.getMessage()); }

Here, throwing = "ex" binds a compatible thrown exception to the ex parameter. This advice is useful for exception logging and monitoring. It does not automatically handle or suppress the exception.

  1. What is ProceedingJoinPoint? Answer: ProceedingJoinPoint is an interface used in @Around advice. It provides information about the intercepted method and allows us to continue its execution using the proceed() method. Example: @Around("execution(* com.example.service..(..))") public Object logExecution(ProceedingJoinPoint pjp) throws Throwable {

    System.out.println("Before method");

    Object result = pjp.proceed();

    System.out.println("After method");

    return result; }

Here: - pjp.proceed() continues the target invocation. - result stores the returned value. - The method returns the original result to the caller. If proceed() is not called, the target invocation does not proceed through this advice.

  1. Can Spring AOP intercept private or final methods ? Answer: No, Spring's proxy-based AOP cannot intercept private methods through the proxy because they cannot be overridden. Similarly, CGLIB cannot override final methods or subclass final classes. JDK dynamic proxies intercept calls made through the proxied interface, not direct calls to private or final implementation methods. If we need to advise these kinds of join points, AspectJ weaving may be an alternative.
  2. What is the difference between @After and @AfterReturning? Answer: The main difference is that @After executes after the method finishes regardless of success or failure, whereas @AfterReturning executes only after successful completion. @After @AfterReturning Executes after normal or exceptional completion. Executes only after normal completion. Similar to a finally block. Runs after a successful return. Does not provide a returning attribute for binding the result. Can access the returned value using returning. Useful for cleanup and completion logging. Useful for logging successful results. Example: Use @After to log that a method has finished, and @AfterReturning to log the user object returned by a successful service call.
  3. How do you apply an aspect to a specific package or class? Answer: We use pointcut expressions such as execution() and within() to select methods in a specific class or package. Example 1: Target a specific class @Before("execution(* com.example.service.UserService.*(..))") public void logUserService() { System.out.println("UserService method called"); }

This expression matches method executions in UserService. Example 2: Target types in a package @Before("within(com.example.service.*)") public void logServiceMethods() { System.out.println("Service method called"); }

This expression selects methods declared within types directly in com.example.service.

The AOP vocabulary in one aspect

import org.aspectj.lang.annotation.*;
import org.aspectj.lang.*;
import org.springframework.stereotype.Component;

@Aspect                          // a module of cross-cutting logic
@Component
public class LoggingAspect {

    // Pointcut: WHERE advice applies
    @Pointcut("execution(* com.jack.service.*.*(..))")
    void serviceMethods() {}

    @Before("serviceMethods()")                    // advice type: BEFORE
    public void before(JoinPoint jp) {
        System.out.println("entering " + jp.getSignature().getName());
    }

    @AfterReturning(value = "serviceMethods()", returning = "result")
    public void afterReturn(JoinPoint jp, Object result) {
        System.out.println("returned " + result);
    }

    @AfterThrowing(value = "serviceMethods()", throwing = "ex")
    public void onError(JoinPoint jp, Exception ex) {
        System.out.println("failed: " + ex.getMessage());
    }

    @After("serviceMethods()")                     // finally-style
    public void after(JoinPoint jp) { /* always runs */ }
}

@Around — the most powerful advice

@Around("serviceMethods()")
public Object time(ProceedingJoinPoint pjp) throws Throwable {
    long start = System.nanoTime();
    try {
        return pjp.proceed();          // invoke the real method
    } finally {
        long ms = (System.nanoTime() - start) / 1_000_000;
        System.out.println(pjp.getSignature() + " took " + ms + " ms");
    }
}

Common pointcut expressions

// execution(modifiers? return-type declaring-type?name(params) throws?)
@Around("execution(public * com.jack..*Service.*(..))")   // all Service beans

@AfterReturning("within(@org.springframework.stereotype.Service *)")  // inside @Service

@Before("@annotation(com.jack.annotation.Audited)")       // beans carrying a marker
public void audited(JoinPoint jp) { /* only methods annotated @Audited */ }

@Before("bean(orderService)")                              // a specific bean

@Around("execution(* com.jack..*(..)) && args(java.lang.Long, ..)")  // first arg Long

A practical use: retry via AOP

@Around("@annotation(Retryable)")
public Object retry(ProceedingJoinPoint pjp) throws Throwable {
    for (int attempt = 1; attempt <= 3; attempt++) {
        try {
            return pjp.proceed();
        } catch (RuntimeException e) {
            if (attempt == 3) throw e;
            Thread.sleep(200 * attempt);
        }
    }
    throw new IllegalStateException("unreachable");
}

interface Retryable {}        // marker annotation: @Retryable on any method
