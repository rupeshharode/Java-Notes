  1. What is session management?

Session management is a mechanism used to maintain user-specific information across multiple HTTP requests.

HTTP is a stateless protocol, which means the server does not automatically remember a user's previous requests.

For example, when a user logs in to a website, the server needs to recognize that user when they visit another page without asking them to log in again.

Session management helps maintain this state.

  1. Different ways to implement session management

There are four commonly discussed techniques:

HttpSession

Cookies

URL rewriting

Hidden form fields

  1. HttpSession

HttpSession is an interface used to store user-specific data on the server across multiple requests.

Example // Create or retrieve the session HttpSession session = request.getSession();

// Store data session.setAttribute("username", "Jack");

// Retrieve data String name = (String) session.getAttribute("username");

// Remove data session.removeAttribute("username");

Important interview point: The session object is available across requests for the same session, but it is not a single shared object for the entire application. Each user/session has its own session.

  1. Cookies

Cookies are small pieces of data stored in the user's browser.

The server sends a cookie to the browser, and the browser sends it back with subsequent matching requests.

Example // Create a cookie Cookie cookie = new Cookie("username", "Jack");

// Send cookie to browser response.addCookie(cookie);

To retrieve cookies:

Cookie[] cookies = request.getCookies();

if (cookies != null) { for (Cookie cookie : cookies) { if ("username".equals(cookie.getName())) { String name = cookie.getValue(); } } }

Important: Cookies are stored on the client side, not in the server's session storage.

  1. URL rewriting

In URL rewriting, session-related information is added to the URL.

Example:

String url = response.encodeURL("profile.jsp");

The server may append a session ID to the URL if necessary, such as:

profile.jsp;jsessionid=ABC123

This technique can help maintain a session when cookies are unavailable.

Three session-tracking techniques

import jakarta.servlet.http.*;
import java.io.IOException;

@WebServlet("/visit")
public class VisitServlet extends HttpServlet {
    @Override
    protected void doGet(HttpServletRequest req, HttpServletResponse resp)
            throws IOException {

        // 1. HttpSession — server-side state keyed by a cookie (JSESSIONID)
        HttpSession session = req.getSession();      // creates if absent
        Integer visits = (Integer) session.getAttribute("visits");
        session.setAttribute("visits", visits == null ? 1 : visits + 1);

        // 2. Cookie — client-side state sent with every request
        Cookie theme = new Cookie("theme", "dark");
        theme.setMaxAge(7 * 24 * 60 * 60);           // 7 days
        theme.setHttpOnly(true);                     // not readable by JS
        resp.addCookie(theme);

        // 3. URL rewriting — fallback when cookies are blocked
        String encoded = resp.encodeURL("/visit");
        resp.getWriter().println("<a href='" + encoded + "'>again</a>");
    }
}

Session lifecycle and timeouts

import jakarta.servlet.http.*;

class Lifecycle {
    void demo(HttpServletRequest req, HttpServletResponse resp) {
        HttpSession session = req.getSession(true);      // get or create
        session.setMaxInactiveInterval(30 * 60);         // 30 min idle timeout
        session.setAttribute("user", "Jack");
        session.getId();                                  // JSESSIONID value
        session.isNew();                                  // just created?
        session.invalidate();                             // log out: destroy it
    }
}

Session management in Spring (and when to skip sessions)

// Spring Security remembers the login in the JSESSIONID cookie by default.
http
    .sessionManagement(session -> session
        .maximumSessions(1)                    // one login per user
        .expiredUrl("/login?expired"));

// For REST APIs prefer stateless auth: send a JWT in the Authorization
// header instead of storing state in the server session.
http.sessionManagement(s -> s.sessionCreationPolicy(
        SessionCreationPolicy.STATELESS));

Cookies vs sessions at a glance

// | Aspect     | Cookie                  | Session                        |
// |------------|-------------------------|--------------------------------|
// | Stored in  | client browser          | server memory/DB               |
// | Capacity   | ~4KB, limited count     | large, any object              |
// | Security   | user can read/edit      | only the ID travels            |
// | Lifetime   | you set expiry          | until timeout/invalidate       |
// | Use for    | theme, tracking ID      | login state, cart, workflow    |
